# End-to-End Network Traffic Analyzer

## Overview

This project introduces an **End-to-End Network Traffic Analyzer**, a system designed to classify network traffic and provide human-readable explanations for its decisions. It consists of two primary components:

1. **CyberClassifier**  
   A network traffic classifier based on an **XGBoost** model with optimized hyperparameters. It is trained on the **Bot-IoT dataset** to classify network traffic as either normal or one of the following types of attacks:  
   - **DoS (Denial of Service)**  
   - **DDoS (Distributed Denial of Service)**  
   - **Service Scan**  
   - **Keylogging**  
   - **OS Fingerprinting**  
   - **Data Exfiltration**

2. **CyberExplainer**  
   A **Llama 3** model fine-tuned to explain CyberClassifier's decisions. It leverages:  
   - **Input data** provided to the classifier.  
   - **SHAP (SHapley Additive exPlanations)** values generated by the classifier.  
   - Domain knowledge and annotations of decent quality (generated by ChatGPT 4o).  

This fine-tuning process was driven by a curated dataset of prompts and explanations, aiming to provide clear, detailed, and actionable insights for each classifier decision.

---

## Key Features

1. **Streamlit Application**  
   The system is packaged as an interactive Streamlit app, simulating:  
   - **Manual Input of Traffic Data**: Users can input network traffic details such as source address, destination IP, etc.  
   - **Chatbot Interface**:  
      - Explains classifier decisions.  
      - Provides general cybersecurity and network traffic knowledge.  
      - Offers in-depth explanations of decisions upon request.

2. **Ease of Deployment**  
   - Includes pre-built **tests** to validate the system.  
   - A **Docker image** for seamless deployment into production environments.

## Why This Approach?

### Data Quality and Annotation Challenges  
High-quality annotations for training CyberExplainer required domain expertise in cybersecurity. A cybersecurity expert would need to:  
- Analyze traffic data and SHAP values.  
- Provide meaningful explanations for classifier decisions.  

This process is time-intensive, and generating a sufficiently large dataset could take over a year. Instead, leveraging ChatGPT to generate high-quality annotations allowed for faster development while maintaining explanation quality.

### LLM Selection  
While Llama 3 served as a robust base for CyberExplainer, the choice of LLM could be improved. An ideal solution would involve using a **cybersecurity-specific agent**, trained on data tailored to cybersecurity domains. Unfortunately, no instruct models specialized in cybersecurity were available at the time of development.

## Future Improvements

1. **Specialized Cybersecurity Agent**  
   Developing or fine-tuning an LLM on a cybersecurity-specific dataset could improve explanation quality and provide deeper insights into network traffic.

2. **Automated Data Extraction**  
   Automating the process of network traffic data input would enhance usability and streamline the analysis pipeline.

3. **Expanded Attack Coverage**  
   Adding more attack types to the classifier could increase its versatility and real-world applicability.

## Getting Started

### Prerequisites
Check "requirements.txt" for the required packages.

### Installation
1. Clone the repository:  
   ```bash
   git clone <repository_url>
   ```
2. Build and run the Docker container:  
   ```bash
   docker build -t network-traffic-analyzer .
   docker run -p 8501:8501 network-traffic-analyzer
   ```
3. Access the application at `http://localhost:8501`.
